RV64I Pipelined Processor

A 64-bit, five-stage in-order RISC-V pipeline with data forwarding, hazard detection, stalling, and branch flushing.

The processor implements 49 of the 52 instructions of the RV64I base integer ISA across a classic IF, ID, EX, MEM, WB pipeline. Classified as SISD under Flynn's taxonomy, it exploits instruction-level parallelism by overlapping the execution of multiple instructions. Dedicated modules handle the pipeline's hard parts: a multi-path forwarding network resolves read-after-write dependencies, a hazard unit stalls on load-use cases, and a branch unit flushes wrong-path instructions when control flow is redirected.

Hazard handling

Forwarding is split into dedicated paths: EX/MEM to EX, MEM/WB to EX, MEM/WB to MEM for store data, and MEM/WB to ID, with the newer EX/MEM result taking priority when both stages hold the same destination register. The register file deliberately does not rely on negative-edge write and read timing to resolve same-cycle dependencies; an explicit MEM/WB-to-ID path supplies the pending value instead, avoiding half-cycle timing paths between opposite clock edges.

A load immediately followed by its consumer stalls the pipeline and inserts a bubble. Branches resolve in EX, so a taken branch or jump invalidates the two younger instructions in IF and ID and redirects the PC to the target.

Verification

Each mechanism has a directed assembly test with an expected register and memory state, checked in RTL simulation: every forwarding path, forwarding priority, load-use stalling, and branch flushing. An integrated test then combines them in one continuous instruction stream with dependencies, load-use stalls, a taken BEQ, JAL, and JALR, and confirms that the flushed instructions never write their registers and that x0 stays zero.

The design was also verified through synthesis and post-synthesis gate-level simulation.

Running compiled C

To check the core against real software, a C program implementing 64-bit shift-and-add multiplication, without the M extension, is compiled with the RISC-V GNU Toolchain for rv64i, linked with custom startup code, and loaded into instruction ROM as a HEX image. The core returns the correct product in x10.

Timing evaluation: adder choice in the datapath

The project's focus is microarchitecture rather than peak frequency, but synthesis-based timing analysis shows how much the adder in the datapath matters. The baseline ripple-carry adders in the target-address and ALU datapaths were swapped for a 64-bit Kogge–Stone adder and a hierarchical carry-lookahead adder (two 32-bit blocks), reusing the designs from the High-Performance Adder Architectures project. Results are Sky130HD.
