Harvard Processor

A parameterized, multi-cycle Harvard-architecture processor built from 12 coordinated RTL modules.

The processor follows a Harvard architecture: separate program and data memories, a custom instruction set, a hardwired control unit, and a multiplexer-based internal data bus. It's demonstrated at 8 bits but parameterized to any data width at instantiation. Twelve independent modules, the ALU, registers, program counter, ROM, RAM, memory address register, flags register, instruction register, T-state counter, and control unit, are coordinated through T-state sequencing into one multi-cycle datapath.

Verification

The RTL is verified with both classical Verilog testbenches and self-checking cocotb testbenches, across three strategies: directed tests for reset, load, hold, increment, and control priority; randomized tests validated in Python against a software reference model; and, for combinational modules like the ALU, exhaustive tests covering every possible input combination.

Amdahl's Law study: removing the MAR

An architectural study examined what happens when the Memory Address Register is eliminated from the datapath, letting memory be addressed more directly. Before the change, 84% of the ISA executed in 2 T-states; after it, 100% did, giving every instruction a uniform 2-cycle execution time. Amdahl's Law was used to validate the change: with the serial (non-optimizable) fraction of each program fixed, the predicted speedup from raising the optimized fraction to 100% was checked against the actual, measured cycle counts across three benchmark programs of increasing size.

The larger and more instruction-dense the workload, the more absolute cycles the optimization recovers, exactly the behavior Amdahl's Law predicts once the optimized fraction of execution approaches 100%. Full methodology, workload analysis, and the Amdahl's Law validation are documented in the repository's Architectural Studies folder.
